# `qgeom/hal/` — 高維合體運算的硬體抽象層

> **架構位置**：`architecture.json` 的套件 `qgeom-hal`，聯邦 `accel`（qgeom 子聯邦），**Layer 1**，
> `depends_on: [qgeom-core]`。只匯入 `qgeom/core` 與 `moonbitlang/core`。

## 1. 一句話定位

「高維合體（fused）運算的硬體抽象層」不是一個比喻：這裡有一條**可以被反例推翻的契約**，
以及三個**走訪順序不同**的後端來檢驗它。

* 抽象邊界是 `FusedBackend` trait —— 它只承諾名字、向量道寬度、分塊跨度，**不承諾走訪順序**。
* 後端直譯器（interpreter）把 `Plan`（一連串 `Stage`）跑成張量；
  `ScalarCore`（純量）、`LaneCore`（道內交織）、`BlockedCore`（分塊）用不同的位置順序填輸出。
* **合體（fusion）的定義**就是本套件的中心定理：
  `contract(τ₀₁T, 0) = contract(T, 1)` —— 先交換再收縮，等於直接收縮另一軸。
  一個「把交換吸收進收縮」的合併規則能省掉一整趟遍歷，而且**結果逐位元相同**。

## 3. 得到的定理（含算出的數字）

### 3.1 單步語意與合體恆等（4 命題）

| 標籤 | 敘述 |
|---|---|
| 單步一致 | 4 個 `Stage` 的語意與 `qgeom/core` 的 `ct_permute`／`ct_contract_axis` **逐位元一致** |
| **合體恆等** | `contract(τ₀₁T, 0) = contract(T, 1)`（形狀 `(2,2)`） |
| 全收縮不變量 | `sum(τT) = sum(T)`（值 **156**） |
| 對純量線性 | `sum(cT) = c·sum(T)`，`c = 3/2` |

### 3.2 後端等價（2 命題）

18 條可執行計畫 × 7 個後端 = **126 次比較，結果全部相同**；
負控制：非法收縮軸／非法交換軸在**所有**後端都回傳 `None`（不是只有參考實作會擋）。
這一章就是「抽象層存在」的可檢驗定義：換後端不改語意。

### 3.3 合併代數、正規化與流量（7 命題）

| 標籤 | 敘述 | 驗證 |
|---|---|---|
| 結合律 | `(p∘q)∘r = p∘(q∘r)` | 結構相等 |
| 直譯等價 | `exec(p∘q) = exec(q)∘exec(p)` | 逐步 vs 一次跑完 |
| 正規化 | `exec(simplify p) = exec(p)`（6 條計畫） | 語意保存 |
| 冪等 | `simplify(simplify p) = simplify p`，且步數不增（共省下 **4** 步） | 計數 |
| 流量 | 三連逐元素步：未合併 `3N = 36`，合併後 `N = 12` | 模型計數 |
| 單調 | `fused ≤ unfused`，3 條計畫**嚴格**下降 | 模型計數 |
| 全合併 | 只有逐元素步的計畫合併後只剩**一趟**（`N = 12`） | 模型計數 |

### 3.4 分塊覆蓋與向量道（3 命題）

* **312 組** `(n, span)`（`n = 1..39`、`span = 1..8`）：分塊**恰好覆蓋每個位置一次**（逐位置計數全部為 1）。
* **28 組** `(後端, n)`：走訪順序都是 `0..<n` 的**排列**（位置總和 `= n(n−1)/2`）。
* **312 組** `(n, lane)`：道覆蓋足夠、浪費 `< lane`（最大浪費 **7**）。

### 3.5 決定性、純度與無別名（4 命題）

同一計畫兩次結果相同；輸出是新緩衝（**改動輸出不影響輸入**）；執行不就地改寫輸入張量；
**後端標籤不進結果**（7 個後端同值）。

## 4. 邊界

三個後端都是**同一個 wasm 目標上的排程模擬**（差別只在走訪順序），不是真實 SIMD／GPU 後端；
流量是**計數模型**（每趟一個單位 × 元素數），不是量測值。這裡證明的是「介面契約＋合併規則的一致性」，
不是「某張顯示卡上比較快」。
